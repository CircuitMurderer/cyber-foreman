# SPEC-014：LLM 辅助语义监督

- 状态：ACCEPTED
- 创建日期：2026-10-08
- 最后更新：2026-10-08

## 背景

确定性规则可以可靠处理超时、断联、Git 边界和测试结果，但无法判断 Agent 的自然语言答复是否明显偏题。内网部署通常提供 OpenAI-compatible 的 Qwen，因此需要一个可替换、低优先级且故障安全的语义复核层。

## 目标

- 在确定性验证通过后，对完整 Agent 可见回复做保守语义复核。
- 发现明确偏题时，在独立预算内自动追加纠偏指令。
- 先用 DeepSeek/OpenAI-compatible 接口验证，部署时只改配置即可切换到 Qwen。
- 将复核开始、结论、错误和实际纠偏记录为持久事件，并在前端展示。

## 非目标

- 不读取或评判模型隐藏思维链。
- 不让 LLM 覆盖 Git、测试、超时、权限或命令白名单结论。
- 不主动读取源码、diff、工具原始输出或密钥发送给复核模型；操作员指令本身的内容除外。
- 本阶段不实现 Anthropic 或 Google 格式的监督模型接口。

## 功能要求

- REQ-001：配置支持 OpenAI-compatible `base_url`、`model`、可选 `api_key_env` 和超时。
- REQ-002：确定性验证失败时不得调用语义复核来改变结论。
- REQ-003：输入只包含有界的可信指令、当前可见回复和验证摘要，并明确标记 Agent 回复为不可信数据。
- REQ-004：输出必须严格解析为 `pass`、`redirect` 或 `uncertain`；`redirect` 必须包含具体 follow-up。
- REQ-005：每个操作员回合使用独立 `max_semantic_redirects` 预算，默认 1，0 表示禁用自动纠偏。
- REQ-006：网络、超时、HTTP、解析及预算耗尽均 fail-open，不得使已通过确定性验证的任务失败或无限循环。
- REQ-007：需要 API key 时只能从环境变量读取，不写入配置、日志、事件或错误；无鉴权内网端点可以省略变量名。
- REQ-008：前端时间线与任务总结展示复核结果，自动纠偏计入监工决策。

## 验收标准

- AC-001：单元测试覆盖 OpenAI 请求、严格 JSON 解析、密钥不泄露和配置校验。
- AC-002：集成测试覆盖一次 redirect 后 pass、预算限制和 reviewer 故障 fail-open。
- AC-003：DeepSeek 实际接口返回可解析结论。
- AC-004：全量测试、vet、race、前端检查和生产构建通过。
