# SPEC-019：证据化语义验收

- 状态：IMPLEMENTED
- 创建日期：2026-10-26
- 最后更新：2026-10-26

## 背景

现有辅助监工可以根据操作员指令、Agent 可见回复和受控工具给出语义结论，但结论主体仍是自由文本。模型可能仅依据 Agent 的“已经完成”自述接受任务，也无法在前端清楚区分验收证据、未满足要求和缺失证据。

## 目标

- 让语义复核围绕操作员明确提出的必须项进行验收。
- 要求最终通过、纠偏和人工升级均携带结构化证据。
- 让纠偏指令只处理明确的未满足项。
- 在不暴露命令输出的前提下提供变更文件和验证命令元数据。
- 在任务总结中展示证据、未满足项和缺失证据。

## 非目标

- 不让 LLM 覆盖工作区、测试、权限、超时或预算结论。
- 不把 Agent 隐藏思维、工具原始输出或验证命令原始输出发送给复核模型。
- 不自动开启工作区 diff；完整 diff 继续由 `allow_workspace_diff` 显式控制。
- 不把模型生成的证据当作可执行命令或新的权限来源。

## 功能要求

- REQ-001：最终 `pass` 必须包含至少一条有界证据；运行中 `pass` 只表示继续观察，可不要求完成证据。
- REQ-002：`redirect` 必须同时包含具体 follow-up、未满足要求和支持该判断的证据。
- REQ-003：`uncertain` 必须列出无法判断所缺少的证据。
- REQ-004：`attention` 必须包含支持高风险歧义的证据。
- REQ-005：证据类列表最多八项，单项必须限长，空项必须移除。
- REQ-006：`inspect_task_state` 必须返回有界变更文件列表及验证命令的状态元数据，不得返回命令参数和原始输出。
- REQ-007：启用 tool calling 的最终复核必须先调用 `inspect_task_state`，再允许模型选择终态动作。
- REQ-008：复核事件必须持久化证据、未满足要求和缺失证据，前端任务总结必须展示这些字段。
- REQ-009：语义纠偏仍必须经过既有 Decision、Executor、去重和预算路径。

## 验收标准

- AC-001：测试证明无证据的最终通过会被拒绝。
- AC-002：测试证明结构化纠偏可以解析并保留证据与未满足要求。
- AC-003：测试证明任务状态工具提供变更与验证元数据但不泄露命令输出。
- AC-004：前端类型检查和生产构建通过，任务总结可以显示结构化验收结果。
- AC-005：全量 Go 测试通过。
