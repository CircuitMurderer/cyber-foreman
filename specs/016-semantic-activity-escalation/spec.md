# SPEC-016：Agent 活动检查与人工升级

- 状态：IMPLEMENTED
- 创建日期：2026-10-08
- 最后更新：2026-10-08

## 背景

受控语义工具已经能查看任务状态和生命周期，但无法回答“Agent 是否真的调用过测试、编辑或权限工具”。同时，某些高风险歧义不适合继续自动追加指令，需要明确交给操作员处理。

## 目标

- 提供经过脱敏的 Agent 工具活动摘要，帮助辅助监工判断实际执行轨迹。
- 提供显式、可关闭、受预算约束的人工升级动作。
- 保持确定性规则优先，模型仍不能直接操作 Agent、Shell 或文件系统。

## 非目标

- 不发送工具参数、命令文本、文件内容或原始工具输出。
- 不在 Agent 正在运行时调用 LLM 或执行中断。
- 不让人工升级成为绕过失败验证或权限边界的成功路径。

## 功能要求

- REQ-001：`inspect_agent_activity` 最多返回 20 条工具状态或权限请求摘要。
- REQ-002：活动摘要只包含时间、序号、工具类型/状态和权限请求计数；可能内嵌命令的展示标题也不发送。
- REQ-003：原始参数、命令、文件内容、工具输出和权限选项内容不得进入模型上下文。
- REQ-004：`request_operator_attention` 仅在 `allow_operator_attention=true` 时向模型声明。
- REQ-005：人工升级转换为 `attention_required` Decision，并使用独立 `max_semantic_escalations` 预算。
- REQ-006：未启用、预算耗尽、非法或失败的升级请求均 fail-open。
- REQ-007：交互任务进入 `attention_required` 后保留 Agent session，允许操作员继续对话。

## 验收标准

- AC-001：测试证明 Agent 活动摘要不会泄露原始命令和输出。
- AC-002：测试覆盖显式启用人工升级、未启用时拒绝及预算扣减。
- AC-003：REST API 和前端可配置人工升级预算。
- AC-004：全量测试、vet、race 和前端构建通过。
